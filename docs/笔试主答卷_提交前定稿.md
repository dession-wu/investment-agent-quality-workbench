# 投资 Agent 回答质量与个性化治理平台

作品版本：v0.7.3；材料日期：2026年11月19日。

产品地址：https://podnotes.cloud/investment/

源代码：https://github.com/dession-wu/investment-agent-quality-workbench

## 1. 我选择解决什么问题

投资问答的困难不只是“回答得像不像专家”，而是流畅回答中可能混入错误口径、过期证据或被画像改变的必要风险。一次模型或Prompt升级后，产品经理需要知道：发现的问题是否确实修复、有没有新增问题、哪些结论仍缺证据。

目标用户是投资问答产品经理，研究、测试和合规人员参与查证与复核。本作品把一次版本评审作为核心任务：固定范围→执行与核验→人工复核→建立候选→同基准比较→保存限定决定。不是投资推荐工具，也不自动完成生产发布。

“排查材料分散、口径误判、版本修复难确认”是待访谈的需求假设，当前没有真实机构访谈或线上效率数据。我先用窄场景检验流程是否可执行，而不编造大规模业务收益。

## 2. 产品中什么不能因画像改变

采用三层治理：

| 层次 | 原则 | 示例 |
| --- | --- | --- |
| 客观事实与证据状态 | 同时点、同口径下保持一致；无法核验就如实未知 | 单季扣非同比8.2%不能因用户激进改成累计45% |
| 必要风险与边界 | 不因风险承受能力高而删除；不能承诺收益或代作直接交易决定 | 应收逾期18%的回款/减值风险对保守、激进用户均适用 |
| 表达适配 | 可调整术语、详略和解释次序 | 新手解释单季/累计差异，熟练用户更紧凑展示口径 |

KYC只取构造的知识水平、风险承受能力和期限，不使用真实身份、资产或持仓。配对测试应固定问题、证据及版本，只改变画像；两侧都需对照参考，不能把“两边一样”直接当作正确。

热点上下文需区分传闻、观点、已确认事实，保留可获得时间与更正关系。历史回答在新时点不再适用，不等于原生成模型在历史时点答错；当前展示复评不能计作模型修复率。这部分已形成设计及旧原型，本服务端尚未完成热点场景迁移。

## 3. 质量标准如何变成可计算检查

先判断用户意图，再选必检项，避免用一个平均分掩盖严重问题。

| 意图 | 标准与计算 | 当前落地 |
| --- | --- | --- |
| 财务指标 | 实体、指标、期间、合并口径、币种和单位一致；十进制比较原值或正确舍入值 | 服务端已实现窄字段；F02/F07共2母题3变体 |
| 行情查询 | 价格类型、快照时点、交易状态、单位和基准匹配；缺失/超时不当0 | 已形成规则设计，未迁移实时数据主链路 |
| 热点解读 | 来源支持、当时可获得性、更正和推断边界 | 设计与旧原型；未完成服务端真实验证 |
| 跨意图安全与个性化 | 核心任务回应、必要风险保留、收益承诺及交易指令检查 | 当前窄场景支持；非完整金融合规判定 |

单项状态为PASS、FAIL、UNKNOWN、NA；运行状态独立记录。必检项不能用NA逃避，未知项不算通过。测试范围有阻断时不能保存通过决定，人工处理意见也不能解除阻断。

计划衡量四组指标：①严重错误检出与误拦，分母分别是独立金标错误项和正确项；②关键未知/未执行覆盖率，留在全部适用必检项分母；③固定范围的版本修复、新增失败与新增未知；④从发现问题到形成有证据决定的人工耗时。需由独立标注与实际任务测量，当前不报告总体准确率或耗时下降百分比。

## 4. 自动、数据、人工和行为反馈的分工

LLM负责回答生成，以及任务、风险语义和核心数值声明抽取。确定性规则负责已定位核心声明的数值与口径。人工负责争议判断、依据补充及限定范围的决定。

平台核验参考与生成证据分列。没有来源时不能让模型记忆充当真值。当前没有扶摇/iFinD权限，以构造资料和历史公开披露快照验证；快照也不自动证明历史时点已可获得。

用户点踩只是调查线索：需区分事实错误、表达不适和预期落差；经补证与人工确认后才能加入回归集。此反馈接入流程已设计、未做成服务端功能，当前处理意见不是生产用户行为反馈管道。

## 5. 版本对比与Bad Case归因

冻结测试范围、核验参考、裁判与规则；候选可修改Prompt或生成证据，不自动继承基线PASS。配置变更和运行绑定保存，决定绑定当前修订，后续判断变化使旧决定失效但保留历史。

例子：F02问第三季度单季扣非同比，构造回答写45%，核验参考是8.2%，45%实际是前三季度累计。平台可定位“声明与参考口径冲突”；不能只凭错答案断言一定是Prompt导致。要区分原始输入缺定义、模型未遵循、抽取错误或证据错误，需要对照实际请求与单变量实验。

历史实验中，B组出现UNKNOWN，补充生成证据的指标定义后单例通过；这支持“证据定义可能是影响因素”的假设，不能证明唯一根因或普遍提升。当前auto不披露固定底层型号，不能将该路由名当作严格模型身份控制。

## 6. 我实际实现了什么

Python标准库HTTP服务、SQLite持久化、原生前端。对象覆盖批次、回答、运行、评估、复核、意见、决定和追加事件。支持会话隔离、幂等提交、修订冲突、部分范围阻断、候选、既有回答重评、失败恢复与只读真实实验归档。

服务端保存原始请求及安全处理后的返回；裁判JSON只允许完整单层外围栏规范化，保留原文，不放宽结构或数值规则。思考内容不会当作回答。实际失败保持UNKNOWN，失败最终状态与评估同事务提交；进程中断后不自动重试。

有密钥实例数据库范围全局最多6次调用，失败也占计数，单次一个变体；输入超限拒绝，生成/裁判预算分别768/1536 tokens。本机累计6/6；次数不是金额封顶。

公网实例独立部署在本人电脑，通过既有公网链路和HTTPS反向代理访问，不配置模型密钥。访客可操作批次、意见、候选和历史实验；真实执行禁用。这样公开可体验、历史证据可追溯，同时避免匿名访客消耗付费额度。当前公网演示仍不能让评审者新跑付费主链路，这是明确的交付限制。

## 8. 如何继续创造落地价值

先让产品经理在真实浏览器完成一次排查任务，记录是否找得到依据、是否误把意见当决定及操作耗时；再补独立金标和F07画像对照，测漏检、误拦与风险保留；随后按真实权限接金融数据，扩展行情和热点。严重问题优先，增加页数和总分大屏后置。

预期价值是降低错误版本被误判通过的风险，并缩短问题定位与修复确认的过程。当前证明的是窄场景流程、异常与追溯机制可执行，尚未证明线上业务收益。
