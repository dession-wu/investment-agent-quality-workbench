# v0.8.3 从模块导航转向任务引导

## 本轮解决的问题

三个停顿节点：首页不知道从何开始，候选建立后不知道接下来做什么，回归页不知道当前结论和完成标准。原解释指南仍保留，但主流程不依赖先阅读指南。

| 节点 | 当前任务 / 当前结论 | 下一步 | 完成标准 |
| --- | --- | --- | --- |
| 首次首页 | 检查数值错误、风险遗漏，了解修复流程 | 体验一次完整排查 | 预置四步结束；不等于真实验证 |
| 已有任务首页 | 上次可访问任务及核验状态 | 继续上次排查 | 进入该任务当前步骤 |
| 初次核对 | 先对照回答和参考，提示为待核对假设 | 开始核对证据，再保存问题记录 | 当前用例问题记录落盘；不改变质量结论 |
| 已保存问题 | 尚未建立待验证版本 | 编写修复方案 | 冻结完整范围的候选建立 |
| 候选未运行 | 修复方案已建立，效果尚未验证 | 有资源时显式运行一次；无资源时另看预置示例 | 全部必检项实际完成；不能继承通过 |
| 核验失败/未知 | 分别指出发现问题或证据不足 | 编写新修复方案/记录待补证 | 原记录保留，新候选完整核验 |
| 全范围通过 | 尚未保存范围结论 | 记录本范围通过结论 | 理由和范围决定保存；不是上线授权 |
| 已归档 | 处理状态已归档，验证进度独立展示 | 可继续查看实际记录 | 归档不代表解决问题或通过 |

## 操作与前后端对应

四步可点击：核对回答、编写修复方案、验证修复效果、记录处理结论。当前/已完成/待处理由问题记录、候选、实际评估、有效决定/处置推导；不会点击一下就写入已完成。第一步的记录按当前用例判断，验证与决定按完整范围判断。

用例页与回归页只有顶部下一步采用强主按钮。保存问题并继续使用原notes接口，成功后才打开方案表单；创建候选后仍进入真实候选页。继续修复从原基线派生新的冻结候选，并保留所选失败候选的规则/材料作为编辑初值；取消表单不切换原选中候选。

首页续办只读取当前会话有权访问的任务ID。本机续办标记7天内有效、存储受限时回退为当前会话任务；不实现账号恢复。新建排查仍仅支持已有预置用例，没有伪装为支持任意自定义回答。

预置入口：从候选进入时直接打开预置回归步骤，持续显示“这不是你刚修改候选的核验结果”，可返回原任务/用例/页面。切换步骤与浏览预置不会发模型请求、写正式评估或产生决定。只有明确点击可执行的运行按钮才可能提交模型任务。

配置对照使用“回答规则（Prompt）、参考材料方案、生成材料、测试范围、核验依据”字段；默认只显示变化，未改变的范围/依据用徽标直接展示，原始JSON仍为高级查看。

后端仅更新VERSION；无新增API、schema、数值核验或预算变更。
